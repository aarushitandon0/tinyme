# Tiny Me evaluation

## Data (developer's laptop only, dummy files, never the real user's screen)
- `eval/screenshots/<app>_<nn>.png` and `eval/elements/<app>_<nn>.json` (frozen element list exactly as the pipeline produced it, including bboxes).
- `eval/labels.jsonl`, one row per (screenshot, goal):
```json
{"id": "explorer_03_a", "screenshot": "explorer_03.png", "elements": "explorer_03.json",
 "app": "explorer", "goal": "find the file I downloaded",
 "history": ["Open File Explorer"], "correct_ids": [17, 18], "expect_cannot_see": false}
```
- Target: 8–10 tasks, 4–5 apps, at least 40 rows. Include some `expect_cannot_see: true` rows (target scrolled off or inside a closed menu) and some icon-only targets.

## Systems
- `pipeline_<model>`: frozen elements → brain → `target_id`. Correct if it is in `correct_ids`, or if `cannot_see_it` matches `expect_cannot_see`.
- `vision_coords_<model>`: Gemma 4 gets the image + goal, returns `{"x": int, "y": int}` in image pixels. Correct if the point is inside any correct element's bbox.
- Optional external closed model behind `--external`: own screenshots only; record which model and the date in results.
- `tuned_qwen` if a Tinker run exists.

## Metrics
- Correct-element rate (overall and per app), JSON validity rate, retry rate.
- Latency: median and p90 for the model call; for live runs also capture / read / total.
- Live only (manual log in `eval/live_runs.md`): task completion rate, recovery rate after a deliberate wrong click.

## Rules
- Temperature 0 and identical prompts across runs; record model tag, Ollama version, machine.
- Never hand-edit results. `results.md` is generated by `run_eval.py`.
- Always include 3 concrete failures with a one-line reason each (e.g. "icon-only button with empty UIA name").
- Small sample: report counts ("31/40"), not just percentages.
